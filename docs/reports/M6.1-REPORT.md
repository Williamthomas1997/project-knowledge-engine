# M6.1 report: hardening (reactive call resolution, shared-logic scope)

Date: 2026-11-17 · Implemented by: Claude (directly) · Based on `docs/reports/M6-REPORT.md` §6 · ADR-018

## 1. Summary

1. **Shared-logic exclusions** are now the default (`SharedLogicStep.DEFAULT_EXCLUDE`). The list adds `helper`,
   `logsupport`, `platform.error` packages, `errorsupport`, `errorresponse` and `errorcontext` to the M5 list (util,
   config, constant, logging, logger, dto, mapper, properties, generated). The `shared-logic-of-api` template (1.1.0)
   uses the same list.
2. **`SHARES_LOGIC_WITH` links service ApiOperations only.** Gateway APIs reach it through their `HANDLED_BY` route.
   - **Migration:** the derivation is a single evidence scope, so re-deriving it invalidates the old gateway pairs.
     Their versions and events are kept.
   - **How to run it:** the new `shared-logic` pipeline re-derives without re-ingesting any code. `code-on-commit`
     does the same on the next commit.
3. **Java call resolution for reactive code.** The extractor still has no library classpath and guesses nothing.
   - **Method references** (`this::x`, `field::x`, `Type::x`) become `CALLS` edges marked `method-reference`.
   - **Typed receivers:** explicitly typed lambda parameters and `this.field` receivers are now typed. Calls inside
     lambdas of Mono/Flux and WebClient chains were already attributed to the enclosing method.
   - **Single implementation:** a call to an interface with exactly one implementation also calls that
     implementation, marked `single-implementation`.
   - **Several implementations** are not dispatched; the call is recorded as `multiple-implementations`.
   - **Every unresolved call now has a reason**, recorded as `<reason>: <call>`. `CALLS` goes to 1.2.0.
4. **Real-repository smoke** before and after: see §5.

## 6. Deviations

1. **Calls on values returned by other calls** (`unknown-receiver-chain`, 1,333) are not resolved. Typing them needs
   the return types of repository methods along the chain, and the library classpath for library return types. This
   is the next step if more reach is needed; it is recorded in ADR-018.
2. **Abstract classes are not treated as single implementations.** Only interfaces with exactly one non-abstract
   implementing class are dispatched.
3. **Solver and declared-type results keep `resolution: resolved`.** I did not split them into new values, so
   graphs without the new patterns do not change and existing fixtures stay valid.
4. **No separate migration step.** The existing scope retraction is the migration: the `shared-logic` pipeline runs
   it without re-ingesting code, and `code-on-commit` runs it on the next commit.
